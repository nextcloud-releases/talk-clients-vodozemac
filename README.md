# talk-clients-vodozemac

Swift bindings of [vodozemac](https://github.com/matrix-org/vodozemac) for the key exchange of end-to-end encrypted calls in Nextcloud Talk. It replaces libolm (OLMKit) in Talk iOS: libolm is deprecated and no longer builds with current Xcode. It stays compatible with the web client, which uses libolm through `@matrix-org/olm`.

## What it provides

The crate in `src/lib.rs` wraps only what the Talk key exchange (spreed `src/utils/e2ee/encryption.js`) needs:

| Swift | |
| --- | --- |
| `VodozemacAccount()` | New Olm account |
| `identityKey()`, `createOneTimeKey()` | Keys sent in `encryption.start` |
| `createOutboundSession(theirIdentityKey:theirOneTimeKey:)` | Session of the side receiving `encryption.start` |
| `createInboundSession(preKeyMessage:)` | Session of the side that sent it, together with the decrypted message |
| `VodozemacSession.encrypt(plaintext:)`, `decrypt(message:)` | |

Sessions use `SessionConfig::version_1()`, the only version libolm supports. `createInboundSession` returns the plaintext because vodozemac decrypts the pre-key message while creating the session and cannot decrypt it again.

The Swift bindings in `swift/Sources/TalkOlm` are generated by UniFFI and committed, since Swift Package Manager builds from the repository. `Package.swift` combines them with `TalkOlmFFI.xcframework` (arm64 device and simulator, iOS 16+).

## Building

[rustup](https://rustup.rs) installs the toolchain from `rust-toolchain.toml`. The XCFramework needs macOS with Xcode.

```sh
./scripts/generate-bindings.sh   # after any API change, commit the result
./scripts/build-xcframework.sh   # build/TalkOlmFFI.xcframework(.zip), prints the checksum
```

## Tests

```sh
cargo test

# Key exchange against @matrix-org/olm, with each side starting once
cargo build --example interop_peer
npm ci --prefix interop
node interop/interop.mjs target/debug/examples/interop_peer

# Swift tests against the local XCFramework, needs the iOS 26.5 simulator runtime (xcodebuild -downloadPlatform iOS)
./scripts/build-xcframework.sh
TALK_OLM_LOCAL_BUILD=1 xcodebuild test -scheme TalkOlm -destination "platform=iOS Simulator,name=iPhone 17,OS=26.5"
```

CI runs all of these, checks that the generated bindings and `THIRD_PARTY_LICENSES.md` are up to date, and runs the REUSE compliance check.

## Releasing

Run the **Release** workflow with a version such as `0.1.0`. It uploads the XCFramework to a GitHub release and tags a commit that sets its URL and checksum in `Package.swift`. `main` keeps the placeholder, so use the package by version.

## Updating vodozemac

Change the pinned version in `Cargo.toml`, run `cargo update -p vodozemac` and the tests, then regenerate:

```sh
./scripts/generate-bindings.sh
./scripts/generate-licenses.sh   # needs: cargo install --locked cargo-about --features cli
```
